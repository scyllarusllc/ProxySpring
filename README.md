# ProxySpring

网站：[proxyspring.com](https://proxyspring.com/)

本项目采用 [Apache License 2.0](LICENSE) 授权。

让代理配置、切换和连接诊断更简单的浏览器扩展与配套网站。

> 首版已包含静态网站和 Chrome 扩展。出口检测使用 getip.cloud，它不提供 VPN、代理或 Tor 标签。住宅与移动网络类型仍未接入。

## 本地运行

网站是 FastAPI + Jinja2 模板，样式用 Tailwind CSS，图标用 Font Awesome Free（打包进 `app/static`，不走 CDN）。`/check` 的检测脚本在访问者浏览器里运行，和扩展共用 `shared/check.ts`。

```sh
make install   # npm ci，并在 .venv 里安装 fastapi、uvicorn、jinja2
make test
make build     # 类型检查，生成网站资源 app/static，并生成 dist/extension
make dev       # 带自动重载的网站
```

`make check` 会做类型检查和测试。`make assets` 只重新生成网站的 CSS、脚本和 Font Awesome；这些生成文件不进 git，部署前要先跑一次。

网站在 http://127.0.0.1:8081 ，路由有 `/`、`/check`、`/privacy` 和 `/healthz`，模板在 `app/templates`。生产环境可用 `.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8081` 放在反向代理后面。在 `chrome://extensions` 加载 `dist/extension`。点击工具栏图标会打开或切到扩展标签页，里面用「连接」「配置」「检测」三个分页。

扩展提供批量导入、规则命中预览和顺序调整。

**导入代理**：连接页和配置页都有 Import proxies，一行一条，支持以下写法，前面可加 `http://`、`https://`、`socks4://`、`socks5://`，不写协议默认 http：

```
204.16.235.167:12323:user:pass
204.16.235.167:12323@user:pass
user:pass:204.16.235.167:12323
user:pass@204.16.235.167:12323
```

导入或手动添加后，新代理自动成为默认代理，并出现 10 秒倒计时：点「Proxy now」立即开启，「Cancel」取消，到点自动开启。生效后会刷新状态，显示代理后的出口 IP。连接页的主按钮是「Start proxy / Stop proxy」。配置页顶部是已保存代理列表，新增条目有高亮动画。

连接页会核对 Chrome 是否实际使用本扩展的 PAC 设置；检测页只测试访问 getip.cloud 的路由，不代表所有保存的代理都已通过测试。扩展把配置放在 `chrome.storage.local`。打开接管后用 PAC 按域名分流；关闭接管会清除扩展写入的代理设置。本地主机名和 127.0.0.0/8 始终直连。HTTP 与 HTTPS 代理可以代填认证；SOCKS 用户名和密码只会被保存并提示 Chrome 无法发送。

## 产品定位

面向需要管理自有代理的用户，提供清晰的配置流程、按网站分流规则，以及可解释的连接检测。代理线路由用户自行提供；ProxySpring 不默认提供或销售代理 IP。

## 计划功能

- **代理配置与导入**：保存多个配置，识别常见代理地址格式，分别管理协议、服务器、端口和认证信息。
- **快速切换与网站分流**：手动切换配置，按域名选择代理，显示当前网站命中的规则及原因。
- **连接诊断**：区分端口不可达、协议不匹配、认证失败、隧道失败和目标网站异常；对无法确定的原因标注未知。
- **VPN / Proxy Checker**：提供独立网站工具页，并在扩展中提供当前连接的检测入口。

## VPN / Proxy Checker

### 检测内容

| 项目 | 计划展示的信息 |
| --- | --- |
| 出口 IP | 当前请求使用的公网 IP、IP 版本及检测时间 |
| 网络归属 | 国家、城市、运营商和 ASN；地理位置为数据库估计 |
| IP 类型 | 数据源报告的住宅、移动网络或数据中心类型 |
| VPN / 代理标签 | 数据源是否将该 IP 标记为 VPN、代理或 Tor，并显示来源与查询时间 |
| 时区一致性 | 浏览器时区与出口 IP 所在地区是否存在明显差异，作为提示而非确定性结论 |
| WebRTC 出口检查 | 在浏览器允许的范围内检查是否出现与网页请求不同的公网出口；未观察到地址不代表不存在泄露 |

### 结果表达与边界

- 使用“该 IP 被某数据源标记为代理”等可追溯表述，不宣称能够确定用户安装了 VPN 或某个代理扩展。
- 数据库标签可能过时或误判；住宅与 ISP IP 也可能被标记为代理。
- 不将时区差异或不同网络出口单独视为使用代理的证据。
- 不保证与其他网站的风控判断一致，也不承诺绕过检测。
- 将“未被标记”“未检测到”“数据源不可用”和“未执行检测”分别展示。
- 网站检测反映访问该网站的请求出口；扩展的分流规则可能使其他网站使用不同出口。

### 用户流程

1. 检查当前连接，展示出口及数据源标签。
2. 解释发现的异常和判断依据。
3. 引导用户在扩展中检查协议、端口、认证及分流规则。
4. 修改配置后重新检测，对比结果。

### 隐私与实现原则

- 代理配置和认证信息优先保存在本地；不发送给 IP 检测服务。
- IP 检测服务会看到连接来源 IP。若向第三方查询指定 IP，应说明服务商、查询内容和用途。
- 第三方服务密钥保存在服务端，不嵌入扩展或网页代码。
- 实现前评估数据源的覆盖、更新频率、许可、费用及保留政策；数据源尚未选定。
- WebRTC 检测由用户主动触发，说明所用 STUN 服务，不请求摄像头或麦克风权限。

## 首版范围

优先完成代理配置、快速切换、按域名分流、基础连接诊断，以及出口 IP / ASN / 地区查询。VPN、代理和 Tor 标签在选定数据源后接入；时区及 WebRTC 检查作为后续增强功能。

目标首先支持 Chrome Manifest V3。协议认证能力需遵循浏览器本身的限制，尤其不能假定扩展可以直接支持带用户名和密码的 SOCKS5 认证。
